# Platform core — implementation plan

> Executed natively in one session (user asleep, told Claude to pick the best option
> everywhere). Steps use checkbox syntax for tracking.

**Goal:** a running control plane with GitHub sign-in, teams, service catalog,
versioned per-environment config and secrets, one authorization policy, an audit
log, a JSON API and an htmx UI.

**Architecture:** one Go binary `cmd/controlplane`, per-domain packages under
`app/` (identity, team, catalog, envconfig, audit) plus `app/authz` and the page
layer `app/web`. Uber fx composition root in `cmd/controlplane/modules`. GORM on
MySQL, golang-migrate with embedded migrations applied on start.

**Tech stack:** Go 1.24, Gin, Uber fx, viper, GORM + go-sql-driver/mysql,
golang-migrate, html/template + htmx 2 (CDN with SRI), Prometheus client,
testify. Hand-written fakes in unit tests (same as go-plateful).

**Spec:** `docs/superpowers/specs/2026-10-07-core-design.md`

## Global constraints

- No comments in any file (user's global rule; hooks enforce it).
- Function bodies ≤ 20 lines, ≤ 2 levels of nesting.
- Config env vars use the `PLATFORM_` prefix, as listed in spec §8.
- The `config` domain is the Go package `envconfig` (avoids clashing with `pkg/config`); its API prefix stays `/api/v1/config`.
- Commits: one per layer (skeleton, storage, rules, handlers), no fix commits, no co-author trailer.

## Review focus

1. A secret value must never appear in API responses, HTML, audit details or logs — a test greps every response for a known secret value.
2. A member editing `prod` config must get 403, not a silent no-op — authz matrix test plus an API test.
3. Removing or demoting the last maintainer by a non-admin is refused — usecase test.
4. A state-changing request without the CSRF token is refused even with a valid session — integration test.
5. Two services claiming the same host, in any environment, is refused — usecase test.
